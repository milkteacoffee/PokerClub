# 赌途（PokerClub）发布前评估报告

> 评估日期：2026-09-15 ｜ 评估范围：法律合规风险、C 端产品成熟度（去商业化对标）、界面交互细节
> 说明：本文为技术与产品视角的梳理，**不构成法律意见**；正式发布前请咨询执业律师与属地出版/网信主管部门。

---

## 0. 一页结论

| 问题 | 结论 | 关键理由 |
|---|---|---|
| **正式发布有法律风险吗？** | **有，且属于「结构性」风险** | 棋牌类网络游戏自 2019 年起版号「一律不予受理」，**国内无合规发行路径**；无版号公开运营本身即违法。当前无资金通道、无收费，属「非营利娱乐」，风险等级可控但不可忽视 |
| **是否已是完美 C 端产品？** | **不是，完成度约 65%** | 玩法内容（六合一+排位+称号+联机）已超同类免费产品；但缺 5 项 P0 能力：**真人匹配、账号体系、新手引导、局内社交、内容安全体系** |
| **交互细节完善吗？** | **核心闭环完善，外围有缺口** | 牌桌/结算/任务/商城等主流程状态齐全；缺口集中在**首次引导、加载与空态一致性、无障碍与横竖屏细节、误操作保护** |

**本轮已顺手补掉**：隐私政策与用户协议弹窗、意见反馈（含诊断信息一键复制）、昵称/签名违规词过滤、触感反馈与开关、过期不实的规则文案纠偏。

## 1. 法律风险评估

### 1.1 监管口径（2026 年现状，已核实）

| 事项 | 现行口径 | 对本作的直接影响 |
|---|---|---|
| **游戏版号** | 面向公众上线运营（含 H5/网页/小程序）必须取得版号；「体量小、无付费」**不豁免** | 本作是公开可访问的 H5 网页游戏，属监管范围 |
| **棋牌类题材** | 2019-04-10 全国游戏管理工作会议明确「**棋牌类一律不予受理**」，执行至今未变 | **这是最致命的一条：本作无法通过正常途径拿到版号** |
| **无版号运营后果** | 责令下架、没收违法所得、罚款（最高可达违法所得 1–5 倍）、情节严重取缔经营、列入行业黑名单 | 一旦被巡查，直接下架 |
| **其他资质** | 付费类需：营业执照 + 软著 + 版号 + ICP + 文网文 + 网安备案 + 防沉迷 | 本作无任何一项 |
| **赌博认定** | 《刑法》303 条、《治安管理处罚法》82 条；两高解释第 9 条：**不以营利为目的、少量财物输赢的娱乐活动不以赌博论处**。实务三条红线：①以营利为目的（抽头/收费/佣金）②虚拟币可**反向兑换**现金或实物 ③面向不特定人长期组织 | 本作①②均无；风险点在于「面向不特定人」+ 主题词汇 |
| **未成年人保护** | 必须接入国家统一实名认证与防沉迷系统；2026 年审核从「有没有」升级为「是否有效」 | 本作无实名、无防沉迷（**当前无付费，故无消费限制问题**，但时长/身份仍属缺口） |
| **个人信息保护** | 《个人信息保护法》最小必要原则；须公示收集规则 | 本作收集昵称/签名/头像/设备标识/对局记录，**此前无任何告知**（本轮已补隐私政策） |
| **内容合规** | 不得含宣扬赌博、淫秽色情、暴力等内容；UGC（昵称/签名/头像）需自审与处置机制 | 「赌」字主题 + 无敏感词体系（本轮已补基础过滤） |

### 1.2 本作风险点逐项体检

| 风险点 | 现状 | 等级 | 建议 |
|---|---|---|---|
| 名称「赌途」+ 游戏内「赌神/赌场/赌桌骰王/赌局」等词汇 | 全站高频出现 | 🔴 高 | **改名 + 去赌博语汇**（如「牌友小馆」「棋乐馆」；把「赌神」改「牌王」） |
| 棋牌题材本身 | 德州/炸金花/掼蛋/21点/骰子 | 🔴 高 | 无版号路径；见 1.3 路径选择 |
| 提供联机对局服务（可组织他人对局） | 好友房 4 玩法 | 🟡 中 | 保持「仅限熟人邀请、无匹配大厅、无抽头」，不提供任何代收代付 |
| 资金通道（充值/提现/交易/广告） | **完全没有** | 🟢 低（加分项） | **永远不要加**；一旦加入即从娱乐跃迁到高危 |
| 虚拟金币与积分 | 不可兑换、无价值 | 🟢 低 | 条款中已声明；继续保持「不可交易、不可转让」 |
| 排行榜公开展示昵称/签名/头像 | 有 | 🟡 中 | 已加过滤与隐私说明；建议补「举报/拉黑」 |
| 自定义头像上传 | 有（≤12KB，服务器截断） | 🟡 中 | 建议加「违规图片人工下架」通道（反馈入口已可承载） |
| 实名/防沉迷 | 无 | 🟡 中 | 若将来面向未成年人可能的公开渠道发布，必须接入；当前建议明确标注 18+ |
| 无隐私政策/用户协议 | **本轮已补** | 🟢 已处置 | 持续维护更新日期 |
| 过期不实文案（「无后端、不收集 IP」） | **本轮已纠正** | 🟢 已处置 | — |
| 素材版权 | 牌面/图标/头像全部自绘 SVG，BGM 为合成引擎 + 用户自备 | 🟢 低 | 保持自研；勿引入未授权素材 |

### 1.3 三条可行路径

| 路径 | 需要做什么 | 风险 | 结论 |
|---|---|---|---|
| **A. 私域自用 / 熟人娱乐**（推荐当前阶段） | 不收费、不投放、不上应用商店、不公开招募；域名不用于商业推广；完成条款与隐私告知（已做）；改名去「赌」字 | 低 | **成本最低、与现状最匹配**。本质是「朋友间娱乐工具」，符合司法解释的娱乐豁免精神 |
| **B. 国内合规商业发行** | 需版号 → 棋牌类不受理 → 必须**转型为非棋牌题材**（去扑克/麻将/骰宝主题，改为纯休闲益智如「牌型连线解谜」）；再配齐营业执照、ICP、文网文、网安备案、防沉迷、实名 | 极高（等于重做产品定位） | 现阶段不现实 |
| **C. 海外发行** | 无需国内版号（Steam/海外 Web）；但需遵守目标平台与当地规则（部分地区「poker」类需博彩牌照）；**不得面向国内推广** | 中（合规成本与语言本地化） | 若目标是「正式发布」，这是唯一可行的商业路径 |

## 2. C 端产品成熟度对标（去商业化，参照欢乐斗地主）

### 2.1 能力矩阵

| 维度 | 行业标杆具备 | 本作现状 | 差距 |
|---|---|---|---|
| 玩法数量 | 1–2 种深耕 | **六合一**（德州/21点/炸金花/猜骰子/骰子比大小/掼蛋） | ✅ 优于标杆 |
| 单机 AI | 多档难度 | 4 档难度 + 4 种性格 | ✅ |
| **真人匹配** | 秒级匹配、按水平分段 | **无**（仅好友房 + 单机 AI） | 🔴 **P0 最大缺口** |
| **账号体系** | 手机号/三方登录、跨端同步、找回 | 设备 ID + 玩家号 + 恢复码（手动接管） | 🔴 P0：换机/清缓存即断社交链 |

| 断线重连/托管 | 自动重连 + AI 托管 | ✅ 有（宽限期重连 + 自动代打） | ✅ |

| 好友系统 | 好友/申请/私聊/赠送 | ✅ 好友（搜索/申请/接受）+ 好友榜 | 🟡 缺私聊与赠送 |
| 排行榜 | 全服/好友/周榜 | ✅ 全服 + 好友 | ✅ |
| 段位与荣誉 | 段位/赛季/称号 | ✅ 六段位 + 39 称号 + 六冠赌神 | ✅ 优于标杆 |
| 任务与成长 | 每日/周常/成就 | ✅ 新手/每日/周常/月度 + 1000 成就 | ✅ |
| 商城与外观 | 皮肤/头像框/道具 | ✅ 15 件（8 外观 + 7 道具，纯金币） | ✅ |
| 经济与保底 | 破产补助、连败保护 | ✅ 救济金 + 惩罚机制 | ✅ |
| 战绩与复盘 | 对局历史、牌谱回放 | 🟡 有战绩/历史，**无回放与分享** | P1 |

| 赛事/活动 | 赛季、限时活动、赛事 | ✗ | P2 |

| 合规与隐私 | 隐私政策、实名、防沉迷、举报 | 🟡 **本轮新增条款/隐私/昵称过滤**；缺实名、防沉迷、举报拉黑 | P0（若公开发布） |
| 触感与音效 | 音效包 + 震动 | 🟡 音效/BGM 有，**震动本轮新增** | P2 扩充音效包 |
| 数据与运维 | 埋点、崩溃上报、灰度 | ✗ | P1 |
| 多语言 | 海外版 | ✗ | P2 |

### 2.2 P0 缺口的具体建议（按投入产出排序）

1. **真人快速匹配**：服务端已有房间/座位/权威状态机，只需加一个「匹配队列」（按玩法 + 段位区间配对，凑满即开局，超时用 AI 补位）。可复用现有好友房全部逻辑，**这是性价比最高的一步**。
2. **账号体系**：把「设备 ID + 恢复码」升级为「手机号/邮箱 + 验证码」（或先做微信/QQ 一键登录），保留现有玩家号作展示。否则排行榜、好友、称号都建立在会丢失的身份上。
3. **新手引导**：首次进入 3 步引导（选玩法 → 看牌型 → 试打一局），牌桌加「牌型提示/可出牌高亮」，掼蛋已有「提示」按钮可复用。
4. **局内社交**：至少补表情/快捷语（预设 12 条，无自由文本 → **同时规避内容审核成本**），服务端广播即可。
5. **内容安全闭环**：昵称/签名过滤已做；再补「举报 + 拉黑 + 头像下架」三件套，以及未成年提示（18+）。

## 3. 界面交互细节审计

### 3.1 状态覆盖

| 检查项 | 现状 | 说明 |
|---|---|---|
| 加载态 | 🟡 部分 | 牌桌「等待发牌」有；排行榜/商城请求中缺统一 loading |
| 空态 | 🟡 部分 | 排行榜有 `board-empty`；好友列表、任务无数据时的空态文案需统一 |
| 错误态 | ✅ 较好 | toast + 网络错误回落（联机明确提示「可手动重试」） |
| 成功反馈 | ✅ 好 | 保存资料/领取奖励/改名均有 toast 与徽标联动 |
| 二次确认 | ✅ 好 | 离桌、退出牌桌、重置横屏均确认 |
| 未完成态提醒 | ✅ 好 | 大厅徽标显示待领取数量，领完归零 |

### 3.2 交互一致性与可用性

| 检查项 | 现状 | 建议 |
|---|---|---|
| 返回路径 | ✅ 统一 | 对局内返回一律回「选择模式」，模式页再回大厅（已统一） |
| 弹窗遮罩 | ✅ 统一 | 走 `openOverlay`，同时只允许一个；确认类不点遮罩关闭 |
| 点击热区 | 🟡 部分 | 牌桌按钮 ≥40px；但部分小图标（复制、关闭）在窄屏偏小 |
| 误操作保护 | 🟡 部分 | 出牌/弃牌无二次确认（**牌局节奏优先，属合理取舍**）；加注用 `prompt` 输入，建议换成滑杆/芯片点选 |
| 连点防抖 | 🟡 部分 | 对局动作有服务端校验兜底；商城购买、领取建议加按钮禁用 |
| 键盘与无障碍 | 🟡 部分 | 掼蛋有 aria/tabindex；德州与联机牌桌键盘支持弱 |
| 横竖屏 | 🟡 部分 | `#stage` 固定 960×540 + 缩放，竖屏走「请横屏」提示；**注意：CSS 媒体查询基于视口宽度，stage 内部元素在竖屏下不会触发窄屏样式**（现联机屏的窄屏适配只在 stage 被整体缩小时生效） |
| 声音解锁 | ✅ 好 | 首次点击解锁策略已处理，BGM 缺失有回落 |
| 长按/选择 | ✅ 好 | 全局禁用文本选择与长按菜单，符合游戏习惯 |
| 首屏性能 | ✅ 好 | 单文件 500KB 左右、无外部依赖、首屏无阻塞请求 |

### 3.3 本轮已修的具体问题

1. 规则页「纯单机、无后端、不收集 IP」文案已过期不实 → 改为准确的联机/数据说明。
2. 缺隐私政策与用户协议 → 新增弹窗（含服务性质、未成年人、信息收集、存储删除、行为规范、免责、变更七节）。
3. 缺反馈渠道 → 新增「意见反馈」，可一键复制诊断信息（玩家号/设备标识/战绩/UA）。
4. UGC 无内容安全 → 新增昵称/签名违规词过滤（广告导流、代充交易、赌博诱导类），大厅改名与资料保存双入口拦截。
5. 触感缺失 → 新增震动反馈（轮到自己轻震、结算胜/败不同节奏）并在设置中可关。
6. `[hidden]` 被 `display:flex` 覆盖导致的隐藏层遮挡问题（上一轮已修，此处记录以免回归）。
